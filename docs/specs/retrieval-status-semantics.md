# 检索工具状态语义

更新时间：2026-06-02

## 目标

统一检索工具的 `status`、`data_gaps`、`warnings` 口径，避免上层 agent 把“工具跑通”误解为“证据完整”。

## 通用规则

| 状态 | 含义 | 上层 agent 行为 |
|---|---|---|
| `ok` | 工具的主目标已经成立，返回的数据可用于回答该主目标 | 可以使用结果，但仍必须检查 `data_gaps` 和 `scope_notes` |
| `partial` | 工具的主目标只被部分证据支持，或者核心记录存在但有效字段不足 | 只能做保守回答，必须说明缺口 |
| `not_found` | 主目标没有命中记录，或核心记录完全缺失 | 不能猜测；如问题仍需回答，调用缺口检测或追问 |
| `needs_clarification` | 必要槽位缺失或实体存在歧义 | 追问用户，不继续使用第一候选 |
| `error` | 工具执行异常 | 不使用结果，报告异常 |

`data_gaps` 表示“当前本地库无法支撑的回答部分”。它可以和 `ok` 同时出现，因为某些工具的主目标已经成立，但附属维度仍缺数据。

## 工具级口径

### `school_profile`

主目标是返回学校级画像。只要学校实体解析成功，且学校基础画像可返回，状态保持 `ok`。

- 无学校级就业摘要行：`ok + data_gaps=["学校级就业/升学摘要"]`。
- 有就业摘要行但只有年份、核心字段为空：`ok + data_gaps=["学校级就业/升学摘要有效字段"]`。
- 有 `employment_data` 或就业率、升学率、薪资、行业/地域/雇主等有效字段：不标就业缺口。
- 学校简称或模糊输入存在多个候选：`needs_clarification`。

原因：学校画像的主目标不等于就业摘要；就业摘要只是画像的一部分。

### `employment_summary`

主目标就是返回学校级就业/升学摘要，因此比 `school_profile` 更严格。

- 无就业摘要记录：`not_found + data_gaps=["学校级就业/升学摘要"]`。
- 有记录但只有年份或核心字段为空：`partial + data_gaps=["学校级就业/升学摘要有效字段"]`。
- 至少一条记录有 `employment_data` 或有效摘要字段：`ok`。

### `school_major_profile`

主目标是学校 + 专业组合画像。

- 有院系专业目录证据，且没有省份/科类/年份上下文或同时命中招生/录取证据：`ok`。
- 只有部分证据链，例如只有目录证据但缺招生/录取上下文，或只有招生计划原始专业名：`partial`。
- 学校或专业实体无法解析且没有替代证据：`not_found` 或上游状态。

### `comparison_query`

主目标是结构化并列对比。

- 所有目标支持结果都是 `ok`：整体 `ok`。
- 至少有一个目标有 `ok` 或 `partial`，但也存在缺口：整体 `partial`。
- 任何目标需要澄清且没有可用目标：`needs_clarification`。

## 验收原则

1. 不用 `ok` 表示“所有字段完整”；`ok` 只表示主目标成立。
2. 不用 `partial` 惩罚附属字段缺失；除非附属字段就是该工具主目标。
3. 不用空对象、空数组或只有年份的记录伪装成有效事实。
4. `needs_clarification` 优先于猜测第一候选。
5. 回答前必须同时看 `status`、`data_gaps`、`warnings`、`scope_notes`。
