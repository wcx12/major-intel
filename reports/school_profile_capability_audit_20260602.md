# school_profile 能力边界审计

日期：2026-06-02

## 审计目标

本次审计不只验证 `school_profile` 是否能跑通，而是判断它返回的检索内容是否足以支撑上层 agent 安全回答“学校概况”问题。

审计对象：`scripts/retrieval_tools.py::RetrievalTools.school_profile`

审计口径：

- 学校实体必须解析正确；模糊输入不能压成第一候选。
- 学校基础、双一流、学科评估、学校级就业摘要应分口径返回。
- 缺数据必须显式进入 `data_gaps` 或 `warnings`，不能用空字段伪装成完整画像。
- 来源表要保留实体解析来源，尤其是简称通过 `entity_aliases` 命中时。
- 学校级就业不能被表达成某专业就业结论。

## 样本矩阵

真实库样本命令均为：

```powershell
python scripts/retrieval_tools.py school_profile --school "<学校输入>"
```

## 发现的问题

### 1. 模糊学校被 `limit=1` 压成第一候选

旧行为：`school_profile("华大")` 内部调用 `school_lookup(..., limit=1)`，导致 fallback 模糊检索只返回第一条，最后错误归一为“清华大学”并继续查画像。

正确边界：`school_profile` 应继承 `school_lookup` 的歧义判断，不能为了画像查询把候选压窄。

处理结果：已改为使用默认候选宽度；`华大` 现在返回 `needs_clarification`，候选列表保留。

### 2. 简称命中后来源表丢失

旧行为：`school_profile("杭电")` 由 `entity_aliases` 解析成功，但最终 `source_tables` 固定为画像表，丢失 `entity_aliases`。

正确边界：高阶工具必须合并上游 lookup 的来源表，否则 agent 无法解释简称从哪里来。

处理结果：已使用 `_merge_source_tables` 合并 `school_lookup` 来源和画像来源。

### 3. 就业摘要缺失没有显式缺口

旧行为：

- `西安电子科技大学` 的 `latest_employment` 是 `{}`，但旧版 `data_gaps` 为空。
- `北京邮电大学` 的 `employment_data` 有结构化字段，但旧版 `school_profile` 没有读取该字段，导致被误判为只有年份。

正确边界：学校画像仍可返回，但就业摘要不能被当成可用证据。

处理结果：

- 无就业行：标记 `data_gaps: ["学校级就业/升学摘要"]`。
- 只有年份，且 `employment_data`、就业率、升学率、薪资、行业/地域/雇主等字段都为空：标记 `data_gaps: ["学校级就业/升学摘要有效字段"]`，并给出 warning。
- 有 `employment_data` 的就业记录会被视为有效摘要线索。

## 剩余边界

- 当前状态仍保持 `ok`，即“学校实体和部分画像可用”。如果产品层希望把缺就业摘要的结果变成 `partial`，需要统一所有画像类工具的状态语义。
- `school_profile` 只返回学校级就业摘要，不能回答“某校某专业就业怎么样”。这类问题仍应调用 `school_major_profile`、`employment_summary` 或缺口检测组合。
- README 中曾写到 `available_fields`、`employment` 等字段，但实现实际为 `latest_employment`，且没有 `available_fields`。后续应清理文档契约，避免测试目标不一致。
- 本次只审计本地库检索完备性，没有联网验证学科评估或就业数据是否是外部最新口径。

## 结论

`school_profile` 经过本次修正后，可以作为学校级画像工具使用，但完备性是有条件的：

- 对学校基础、双一流、学科评估：整体可用。
- 对学校级就业摘要：只有 `data_gaps` 为空且核心字段有值时才可用。
- 对简称和模糊输入：已能区分确认别名、歧义候选和未命中。
- 对专业级就业、录取概率、转专业、校区学费等问题：不在本工具能力范围内，不能越界回答。
