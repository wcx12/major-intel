# school_lookup 能力边界审计（2026-06-02）

## 审计目标

本次审计用真实 MySQL 数据跑 `school_lookup`，再逐条人工判断工具是否真正适合交给上层 agent 使用。判断重点不是命中率，而是边界安全性：

- `ok` 是否真的表示学校实体已经安全解析。
- `needs_clarification` 是否覆盖真实歧义。
- `not_found` 是合理保守，还是别名/抽槽能力缺口。
- fallback 的 `short`、`name LIKE`、`old_name LIKE` 是否造成过度自信或候选排序误导。

## 当前结论

`school_lookup` 现在比旧审计时稳很多，但仍不能算完全完备。

它在“全称、学校代码、内部 `school_id`、已确认唯一别名”上表现稳定；在已 seed 的歧义简称和宽泛词上能返回 `needs_clarification`。旧审计中最危险的一类问题，即短词或宽泛词被 fallback 第一候选包装成 `ok`，已经通过工具层逻辑修复。

当前剩余风险主要是：

- 校区类口语别名需要持续补充；本轮已补 `电子科技大学沙河校区`、`哈工深`、`北邮宏福`、`人大苏州`、`山大威海` 等高频样本。
- raw 自然语言整句不属于本工具职责，必须由自然语言入口先抽槽。
- fallback 候选仍可能较宽，需要通过候选排序、别名 seed 和上层追问继续优化。
- 精确代码查询有时会带出同值 `school_id` 噪声候选，但只要首条是精确代码命中，`ok` 仍可接受。

## 本轮修复

### 1. fallback 多候选不再自动 `ok`

旧问题：`华大`、`电子`、`交通`、`大学` 等输入会因为 fallback 只取第一候选而返回危险 `ok`。

当前行为：当 fallback 命中多个候选，且首条不是精确 `name`、`code` 或 `school_id` 时，返回 `needs_clarification`。

### 2. 当前校名候选优先于旧名候选

旧问题：`中国地质大学`、`师范` 这类查询会被 `old_name LIKE` 命中的历史旧名学校排到当前校名候选前面，候选列表误导上层 agent。

当前行为：fallback 排序中 `name LIKE` 优先于 `old_name LIKE`。复跑后：

- `中国地质大学` 的前两项为 `中国地质大学(武汉)`、`中国地质大学(北京)`。
- `师范` 的前五项为北京师范、华东师范、南京师范、华中师范、东北师范。

### 3. 补充校区/歧义别名 seed

本轮只补库里已有对应学校实体的校区别名，避免把不存在的校区硬映射到本部。

## 已固化的回归测试

- `school_profile` 通过 `school_lookup` 解析学校时不能用 `limit=1` 压掉歧义候选。
- `school_profile` 必须保留别名来源表 `entity_aliases`。
- `school_profile` 缺学校级就业摘要时必须返回 `data_gaps`。
- `resolve_school_sql` 必须让当前校名 `name LIKE` 排在旧名 `old_name LIKE` 前面。

## 剩余缺口

| 缺口 | 当前表现 | 建议 |
|---|---|---|
| 校区别名 | 高频样本已补，但长尾校区别名仍可能缺失 | 定期从真实问题里补 `entity_aliases` |
| 常见校区简称 | `哈工深`、`北邮宏福`、`人大苏州` 等已补 | 后续继续补 `分校/校区/学院` 类常见简称 |
| 地区 + 简称 | `武汉华科`、`浙江的杭电` 这类不是本工具职责 | 自然语言入口先抽 `school_text` 和地区上下文 |
| 宽泛候选解释 | `科技`、`师范` 能澄清，但候选解释仍偏简单 | 后续可补候选排序理由和地区提示 |

## 验收规则

后续判断 `school_lookup` 是否完备，应先守安全性：

1. 全称、代码、内部 id、唯一确认别名可以返回 `ok`。
2. 多个确认别名必须返回 `needs_clarification`。
3. 短词、单字、类别词、宽泛后缀词命中 fallback 时，不应返回 `ok`。
4. fallback 多候选时必须保留候选列表，不能填 `normalized_slots.school_name`。
5. raw 自然语言句子不应直接送进 `school_lookup`；自然语言入口需要先抽出学校槽位。

## 结论

`school_lookup` 当前可以作为学校实体解析工具使用，但完备性仍依赖两件事：持续补 `entity_aliases`，以及上层自然语言入口先做好抽槽。工具自身已经守住“不确定不猜”的核心边界。
